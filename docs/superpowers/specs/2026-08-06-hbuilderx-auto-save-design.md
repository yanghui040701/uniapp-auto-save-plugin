# HBuilderX 自动保存插件设计规格

## 1. 项目定位

本项目面向 HBuilderX，而不是仅面向 uni-app。插件为 HBuilderX 补充类似 VS Code `afterDelay` 的真实文件自动保存能力：用户停止输入一段时间后，即使仍停留在当前编辑器中，也会自动保存当前文件。

插件不重复实现 HBuilderX 已有的“失去焦点自动保存”。HBuilderX 原生功能负责切换标签卡、切换应用和窗口失焦时的保存；插件负责编辑器保持焦点时的延迟保存。两者组合形成完整体验。

## 2. 目标与成功标准

### 目标

- 安装并启用插件后，默认在停止输入 1000ms 后保存当前真实文件。
- 使用真正的防抖：连续输入期间只维护一次待执行保存，不随每次按键重复保存。
- 用户在防抖结束前切换文件或切出 HBuilderX 时，由 HBuilderX 原生失焦保存处理正在离开的文件。
- 首次激活时，经用户确认后协助开启 HBuilderX 原生失焦保存。
- 支持所有本地、可写、已命名的文本文件，不按项目类型或扩展名限制。
- 正常保存完全静默，只有保存失败时才提示用户。
- 提供可直接用于 HBuilderX 插件市场提交的发布文案和资料清单。

### 成功标准

- 在同一文件持续输入时不发生高频保存。
- 停止输入达到配置延迟后，当前文件的脏状态消失，磁盘内容更新。
- 在 1000ms 内切换标签卡时，不会错误保存新标签卡；开启原生失焦保存后，旧标签卡会被 HBuilderX 保存。
- 禁用插件后不再创建或执行延迟保存任务。
- 未命名、只读或非本地文档不会被插件强制写入。
- 保存失败不会造成未捕获异常，也不会在没有新编辑时重复弹错。

## 3. 已选方案

采用“延迟保存插件 + HBuilderX 原生失焦保存”的混合方案。

未采用的方案：

- 轮询活动编辑器并在切换时执行“全部保存”：会产生持续开销，并保存用户未打算保存的其他文件。
- 插件直接写入旧文档对应的磁盘文件：会绕开 HBuilderX 的文档模型、保存生命周期、编码和冲突处理，存在数据损坏风险。
- 仅依赖插件监听标签切换：HBuilderX 公开 API 没有稳定公开所需的活动编辑器切换、窗口失焦和关闭事件，无法可靠实现。

## 4. 用户体验

### 首次使用

1. 插件首次激活。
2. 插件检查自身总开关；默认开启。
3. 插件尝试读取 HBuilderX 原生失焦保存配置。
4. 如果原生功能已开启，不显示提示。
5. 如果未开启或无法确认，显示一次确认提示，说明该功能用于确保快速切换标签页或应用时保存旧文件。
6. 用户选择“开启”后，优先通过 HBuilderX 配置 API 更新原生设置。
7. 如果当前 HBuilderX 版本没有公开或兼容的配置键，插件不直接修改 `settings.json`，而是显示清晰的手动路径：`工具 → 设置 → 常用配置 → 失去焦点自动保存`。
8. 用户选择“暂不开启”后不反复打扰；用户可通过插件命令再次执行检查。

### 日常编辑

1. 用户编辑文档。
2. 插件取消该文档先前的待执行计时器并重新计时。
3. 达到延迟时间后，插件重新验证当前活动文档仍是触发计时的同一文档。
4. 文档仍然可保存且处于脏状态时，执行 HBuilderX 的“保存当前文件”命令。
5. 保存成功不显示任何消息。

### 快速切换

如果用户在延迟时间结束前切换标签卡，旧计时器不得对新活动文件执行保存命令。旧文件的立即保存交给已开启的 HBuilderX 原生失焦保存，从而解决现有插件“切换后计时失效”或“保存错文件”的问题。

## 5. 配置与命令

### 用户配置

首版仅提供两个配置项：

| 配置 | 类型 | 默认值 | 规则 |
| --- | --- | --- | --- |
| `hbuilderx-auto-save.enabled`（启用自动保存） | boolean | `true` | 关闭时立即取消所有待执行计时器 |
| `hbuilderx-auto-save.delay`（自动保存延迟） | number | `1000` | 单位 ms；运行时限制到 `200–10000` |

修改配置后无需重启 HBuilderX：总开关立即生效；延迟值应用于后续编辑事件，现有计时器按新值重新安排或取消。

### 插件命令

- `检查并开启 HBuilderX 原生失焦保存`：重新检测原生设置，并在需要时请求用户确认。

首版不提供文件类型白名单、排除目录、成功通知、大文件阈值或多种保存模式。若实际用户反馈证明有必要，再在后续版本增加。

## 6. 组件边界

### HBuilderX 适配层

唯一直接调用 `hbuilderx` API 的组件。负责订阅文档修改和配置修改事件、读取活动编辑器、执行保存命令、显示错误或确认消息、读取和更新配置。其余组件不依赖 HBuilderX 全局对象，以便单元测试。

### 防抖调度器

负责创建、替换和取消计时器。每个待保存任务记录文档身份；触发时必须再次验证活动文档身份，禁止把旧文档的计时任务作用到新活动文档。

### 保存策略

负责判断是否允许保存：插件已启用、文档为本地已命名文本、不是只读状态、文档仍为脏状态、当前活动文档与任务文档一致。条件不满足时安静跳过。

### 原生失焦保存协调器

负责首次提示、读取/更新 HBuilderX 原生设置以及兼容性降级。它不得直接修改 HBuilderX 设置文件，也不得在用户拒绝后反复提示。

### 发布资料

独立文档保存插件市场提交信息、README 文案、隐私与权限说明、版本更新说明和测试过的 HBuilderX 版本，避免发布时临时拼凑。

## 7. 数据流与状态

插件只维护以下运行时状态：

- 当前是否启用。
- 当前延迟毫秒数。
- 待执行计时器及其对应的文档身份。
- 本次运行中是否正在执行保存，用于避免保存事件造成重入。
- 首次原生设置提示是否已处理。该布尔值写入插件目录内的最小状态文件，不包含代码、路径或账号信息；若目录不可写，则仅在当前 HBuilderX 进程中记忆，并允许下次启动再次提示。插件更新或重装后再次提示是可接受的安全降级。

插件不收集、不上传、不分析用户代码、文件路径、编辑内容或使用数据。

## 8. 错误处理

- 保存命令失败：提示一次包含文件名和简短原因的错误；没有新编辑时不自动重试。
- 配置值越界或无效：使用安全默认值或限制到合法范围，不中断编辑。
- 无法读取或修改 HBuilderX 原生设置：降级为手动操作说明，不直接编辑全局配置文件。
- 文档在计时期间被关闭、切换、变为只读或已由其他操作保存：安静取消本次任务。
- 插件停用：释放全部事件订阅并取消全部计时器。

HBuilderX 关闭、强制退出和崩溃不由插件自行拦截。公开 API 没有稳定的关闭事件时，关闭行为继续由 HBuilderX 的原生保存、提示和热退出恢复机制负责。

## 9. 测试设计

### 自动化测试

- 防抖：连续修改只产生一次保存。
- 重新计时：每次修改都会把触发时间推迟到最后一次输入之后。
- 文档身份保护：计时期间切换活动文件时不保存新文件。
- 总开关：关闭后取消任务，重新开启后恢复监听行为。
- 延迟边界：小于 200、大于 10000、非数字配置均得到安全处理。
- 文档过滤：未命名、非本地、只读、非脏文档不会保存。
- 错误路径：保存失败仅报告一次，后续新编辑可再次尝试。
- 停用清理：没有遗留计时器和订阅。

测试使用可控假计时器和模拟 HBuilderX 适配器，避免依赖真实 IDE。

### HBuilderX 手动验证

- 停止输入 1000ms，确认当前文件写入磁盘。
- 连续快速输入，确认不会每个按键都触发保存或明显卡顿。
- 输入后 1000ms 内切换标签，确认旧文件由原生失焦保存，新文件不被旧计时器保存。
- 切换到其他应用，确认当前文件保存。
- 修改总开关和延迟，确认无需重启即可生效。
- 验证未命名文件、只读文件和保存失败场景。
- 重启、停用和卸载插件，确认没有残留定时行为。

## 11. 兼容性与明确限制

- 仅使用 HBuilderX 公开插件 API 和公开命令；不直接修改 HBuilderX 安装目录或用户设置文件。
- 本机 HBuilderX `5.15.2026070915` 的原生失焦保存键已确认为 `editor.saveOnFocusLost`。实施时仍须先读取并尝试通过 `hx.workspace.getConfiguration("editor").update("saveOnFocusLost", true)` 更新；若目标版本不接受该操作，首版采用确认提示加手动引导，不伪装成已自动开启。
- 插件只能可靠保存触发命令时仍为活动编辑器的文件，因此必须在执行前核对文档身份。
- 插件不承诺在系统强制杀进程、断电或 HBuilderX 崩溃瞬间把内容写入真实文件；此类恢复依赖 HBuilderX 原生临时文件机制。
- 首版优先支持 Windows 上的当前稳定版 HBuilderX；由于只使用跨平台公开 API，代码保持 macOS 可用，并在发布资料中如实列出实际验证平台。
