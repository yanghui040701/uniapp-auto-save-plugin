# 编辑防抖自动保存 1.0.1 提示与命名设计

## 背景

1.0.0 使用 `focusSavePromptHandled: true` 记录“原生失焦保存提示已经处理”。这个状态无法区分三种情况：原生设置本来已开启、用户同意开启、用户明确拒绝。状态文件又位于 HBuilderX 用户数据目录，卸载和重新安装插件不会清除它。因此用户在设置曾经开启后误关 `editor.saveOnFocusLost`，重新安装插件仍不会收到提醒。

本次版本同时把用户可见名称从“自动保存（防抖增强）”统一为“编辑防抖自动保存”，并在介绍中准确说明插件会征得同意后引导开启 HBuilderX 原生失焦自动保存。原计划名称“编辑时自动保存”已被 DCloud 插件市场中的现有插件占用，因此不再作为 `displayName` 使用。

## 目标

- 将版本更新为 `1.0.1`。
- 所有用户可见名称统一为“编辑防抖自动保存”。
- 保持插件 ID `yanghui-auto-save`、内部英文名称和 GitHub 仓库地址不变，使 1.0.0 用户可以正常升级。
- 原生失焦保存开启时保持静默；用户后来误关时，下次激活重新提醒。
- 只有用户明确选择“不再提示”时才永久抑制自动提醒。
- 关闭对话框、提示 API 返回空结果或提示过程异常时不写入抑制状态。
- 主动检查命令始终可以绕过抑制状态。
- 同步 README、CHANGELOG、DCloud 发布资料、市场文案、测试、发布 ZIP 与 GitHub `main`。

## 非目标

- 不修改插件 ID、GitHub 仓库名、配置键或默认防抖延迟。
- 不增加第三个公开配置项。
- 不自动、静默开启 HBuilderX 原生设置。
- 不改变编辑时防抖保存、只读文件保护、活动文档身份校验或保存串行化逻辑。
- 不把本插件描述成只服务于 uni-app；它仍是通用 HBuilderX 编辑器插件。

## 用户可见名称与介绍

以下位置统一使用“编辑防抖自动保存”：

- `package.json` 的 `displayName`；
- 插件配置区标题；
- README 主标题和正文中的插件名称；
- DCloud 插件市场显示名称与发布资料；
- 需要显示产品名的提示或说明文本。

插件 ID 保持 `yanghui-auto-save`，内部英文 `name` 保持 `HBuilderX Auto Save`。

DCloud 市场短介绍使用：

> 为 HBuilderX 提供编辑时防抖自动保存，并可引导开启原生失焦自动保存，避免快速切换文件时遗漏保存。

详细介绍必须说明：插件自身负责停止输入后的延迟保存；HBuilderX 原生失焦保存用于补充在延迟结束前快速切换文件或应用的场景；插件只在用户同意后修改原生设置。

## 提示文案

标题：

> 开启 HBuilderX 失去焦点自动保存

正文：

> 检测到 HBuilderX 的“失去焦点自动保存”已关闭。开启后，即使在自动保存倒计时结束前切换文件或应用，也能保存刚离开的文件。是否现在开启？

按钮：

1. `开启`
2. `不再提示`

直接关闭对话框不等同于点击“不再提示”。

## 状态模型

新状态只表达一个事实：用户明确要求永久抑制自动提醒。

```json
{
  "schemaVersion": 2,
  "focusSavePromptSuppressed": true
}
```

状态仍存储在现有用户数据路径，保持原来的原子写入、Windows 重命名重试和主目录回退行为。状态读取只有在 `schemaVersion === 2` 且 `focusSavePromptSuppressed === true` 时返回“已抑制”。

1.0.0 的 `{ "focusSavePromptHandled": true }` 是含义不明确的旧状态，1.0.1 不把它迁移为永久拒绝。这样，升级用户在原生设置关闭时会收到一次新语义提示。只有随后明确点击“不再提示”，状态文件才会被新结构覆盖。

## 激活流程

自动激活按以下顺序执行：

1. 读取 `editor.saveOnFocusLost`。
2. 如果已开启，直接结束；不创建或更新抑制状态。
3. 如果未开启，读取新抑制状态。
4. 如果已抑制，直接结束。
5. 否则显示提示。
6. 点击“开启”时更新原生设置并重新读取确认；成功后不写入抑制状态。
7. 点击“不再提示”时原子写入新抑制状态。
8. 关闭对话框、返回未知结果或提示失败时不写入状态，下次激活仍可提醒。
9. 自动更新失败时显示现有手动设置路径；失败本身不写入抑制状态。

因为已开启状态不再记为“处理过”，用户以后手动误关原生设置时，下次激活会重新进入提示流程。

## 主动检查命令

命令 ID 保持 `yanghui-auto-save.checkFocusSave`，显示名称随产品命名统一调整。主动执行时：

- 忽略 `focusSavePromptSuppressed`；
- 设置已开启时显示确认信息；
- 设置未开启时显示同一授权提示；
- 用户再次选择“不再提示”时保留抑制状态；
- 用户选择“开启”并成功后，不需要删除抑制状态，因为主动命令未来仍会绕过它，而自动激活继续尊重用户此前的“不再提示”。

## 错误处理与隐私

- 读取设置、读取状态、弹出提示或写入状态失败都不能阻塞插件激活和编辑时自动保存。
- 原生设置更新失败继续使用现有手动开启提示。
- 不记录文件内容、路径、项目名或使用行为。
- 新状态仍只保存一个本地布尔偏好，不联网、不上传。

## 测试要求

使用测试先行覆盖：

- 原生设置已开启时不提示、不写状态；
- 设置关闭且无抑制状态时提示；
- 点击“开启”后更新并复核设置，但不写抑制状态；
- 点击“不再提示”后写入 schema v2 状态，后续自动激活不提示；
- 关闭对话框和提示 API 异常不写抑制状态；
- 旧 `focusSavePromptHandled` 状态不抑制 1.0.1 提示；
- 用户曾经开启、后来误关时重新提示；
- 主动命令忽略抑制状态；
- 并发自动激活与主动命令仍保持 single-flight；
- 名称、版本、市场介绍、README、CHANGELOG 与 manifest 保持同步；
- 普通、严格未处理拒绝模式、metadata 校验和市场 ZIP 打包全部通过；
- ZIP 根目录仍直接包含非空 `package.json`，不能回归到外层目录结构。

## 发布流程

1. 在独立 `codex/` 功能分支完成实现和测试。
2. 生成 `yanghui-auto-save.zip`，记录文件数量、大小和 SHA-256。
3. 通过 GitHub PR 将 1.0.1 合并到公开仓库 `main`。
4. 在 DCloud 后台选择“发布新版本”，上传 1.0.1 ZIP 和同步后的使用说明。
5. 将市场显示名称改为“编辑防抖自动保存”，使用本设计中的短介绍和更新日志。
6. 发布后核对公开详情页的版本、名称、下载入口和搜索索引。

## 验收标准

- 用户首次安装且原生失焦保存关闭时收到提示。
- 用户原生设置开启时不被打扰。
- 用户之后误关设置时，下次激活重新收到提示。
- 用户明确点击“不再提示”后，升级或重装不再自动提示。
- 关闭弹窗不会永久取消提醒。
- 市场、HBuilderX 配置页和文档均显示“编辑防抖自动保存”。
- 1.0.0 用户通过同一插件 ID 升级到 1.0.1。
- GitHub `main`、DCloud 1.0.1 ZIP 和公开文档内容一致。
