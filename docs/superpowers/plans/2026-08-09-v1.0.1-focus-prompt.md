# 编辑防抖自动保存 1.0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 发布 `yanghui-auto-save` 1.0.1，在不改变插件 ID 和自动保存核心逻辑的前提下，修复原生失焦保存提示的永久状态语义，并把所有用户可见名称统一为“编辑防抖自动保存”。原计划名称“编辑时自动保存”已被市场现有插件占用。

**Architecture:** 保持 `extension.js` 的依赖组装和 `focus-save-coordinator` 的 single-flight 边界。把本地状态收窄为“用户明确选择不再提示”，由 `prompt-state` 以 schema v2 原子持久化；协调器先读取 HBuilderX 原生设置，再决定是否读取抑制状态和显示提示；运行时把弹窗结果规范化为 `enable | suppress | dismiss`。测试从存储层、运行时适配层、协调层一路覆盖到真实生产装配、清单、文档与 ZIP。

**Tech Stack:** Node.js CommonJS、`node:test`、HBuilderX Extension API、PowerShell 5.1 打包脚本、Git/GitHub、DCloud 插件市场。

## Global Constraints

- 插件 ID 保持 `yanghui-auto-save`，内部英文 `name` 保持 `HBuilderX Auto Save`，GitHub 仓库地址和两个现有公开配置键保持不变。
- 不新增公开配置项，不静默开启 HBuilderX 设置，不改变编辑防抖、活动文档校验、只读文件保护或保存串行化逻辑。
- 只有用户明确点击“不再提示”时才持久化抑制；关闭弹窗、未知结果、提示 API 失败、设置更新失败都不得写入抑制状态。
- 旧 `{ "focusSavePromptHandled": true }` 不迁移为永久抑制。
- 每个实现任务都按 Red → Green → Refactor 执行；先观察指定测试因缺少新行为而失败，再写最小实现。
- 不改动与本版本无关的 `test/package-validation.test.js` 中用于恶意/边界输入的虚构 `1.0.0` fixture。
- DCloud 上传和正式发布属于外部写操作，只在用户明确授权后执行；此前只生成并核验发布物与填写资料。

- [ ] **Step 3: 实现严格读取与原子写入的新接口**

在 `lib/prompt-state.js` 中把读取函数和公开接口改为：

```js
function readSuppressed(fs, stateFile) {
  try {
    const state = JSON.parse(fs.readFileSync(stateFile, 'utf8'));
    return state.schemaVersion === 2 && state.focusSavePromptSuppressed === true;
  } catch {
    return false;
  }
}

function createPromptState({ fs, stateFile }) {
  return {
    isSuppressed() {
      return readSuppressed(fs, stateFile);
    },
    suppress() {
      let temporaryFile;
      try {
        temporaryFile = temporaryStateFile(stateFile);
        fs.writeFileSync(temporaryFile, JSON.stringify({
          schemaVersion: 2,
          focusSavePromptSuppressed: true
        }), 'utf8');
        publishStateFile(fs, temporaryFile, stateFile);
        return true;
      } catch {
        if (temporaryFile) {
          try {
            fs.unlinkSync(temporaryFile);
          } catch {
            // Temporary-file cleanup is best-effort.
          }
        }
        return readSuppressed(fs, stateFile);
      }
    }
  };
}
```

保留现有随机临时文件名、`RENAME_RETRY_DELAYS`、可重试错误集合和最终状态回读，不降低并发安全性。

- [ ] **Step 2: 增加行为矩阵测试**

至少覆盖以下精确序列：

```text
原生已开启（自动）: native -> 结束；不读 state、不提示、不写 state
原生已开启（force）: native -> enabled-info；不读 state、不写 state
原生关闭且已抑制（自动）: native -> state -> 结束
原生关闭且已抑制（force）: native -> prompt；忽略 state 抑制
选择 enable: native -> state -> prompt -> update；不写 state
选择 suppress: native -> state -> prompt -> suppress；不 update
选择 dismiss: native -> state -> prompt；不写 state、不 update
update 失败: native -> state -> prompt -> update -> manual-fallback；不写 state
```

额外保留并改写已有测试：

- 同步抛错、拒绝 Promise 和带恶意 `then` 的 thenable 不阻塞激活；
- 两次自动调用共用一个 flight；
- 自动 flight 未完成时进入强制调用，`flight.force = true` 必须在读取抑制状态前生效，使该 flight 绕过抑制；
- flight 完成后清空，可再次执行；
- 用户先开启、以后手工关闭的效果通过两次独立 `ensure()` 验证：第一次原生为 `true` 静默，第二次为 `false` 时显示提示。

- [ ] **Step 4: 实现 native-first 协调器**

将 `lib/focus-save-coordinator.js` 的状态辅助函数替换为：

```js
async function isSuppressed() {
  try {
    return await state.isSuppressed() === true;
  } catch {
    return false;
  }
}

async function suppress() {
  try {
    await state.suppress();
  } catch {
    // Persisting suppression is best-effort and must not block the flow.
  }
}
```

`runEnsure` 的核心顺序必须是：

```js
async function runEnsure(flight) {
  try {
    if (await isNativeFocusSaveEnabled()) {
      if (flight.force) await runtime.showNativeFocusSaveEnabled();
      return;
    }

    if (!flight.force && await isSuppressed()) return;

    const choice = await runtime.promptNativeFocusSave();
    if (choice === 'suppress') {
      await suppress();
      return;
    }
    if (choice !== 'enable') return;

    try {
      await runtime.enableNativeFocusSave();
    } catch {
      await runtime.showNativeFocusSaveManualFallback();
    }
  } catch {
    // Activation must remain safe if HBuilderX or local state APIs fail.
  } finally {
    if (currentFlight === flight) currentFlight = undefined;
  }
}
```

保留当前 `ensure()` 对并发 flight 的复用与强制升级：

```js
if (currentFlight) {
  if (force) currentFlight.force = true;
  return currentFlight.promise;
}
```
